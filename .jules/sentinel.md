## 2024-04-21 - [Prevent XSS via Safe DOM Manipulation]
**Vulnerability:** The application used `.innerHTML` for rendering the win banner string interpolation (`${esc(name)} won!`). While the `esc()` function mitigates the immediate XSS risk, relying on custom escape functions combined with `.innerHTML` is an anti-pattern that can lead to regressions if a developer forgets to use the escape function on user-provided data.
**Learning:** The project explicitly favors safe DOM manipulation (e.g., `document.createElement`, `.textContent`, `appendChild()`) over the use of `.innerHTML` to prevent XSS vulnerabilities natively.
**Prevention:** Avoid `.innerHTML` entirely for dynamically constructed content that includes user-provided data (like player names or titles). Use the DOM API (`document.createElement` and `node.textContent`) to ensure the browser natively treats all user input as text, effectively neutralizing XSS vectors without relying on string escaping functions.
